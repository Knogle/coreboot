# ASRock Rack B565D4-V1L

This experimental AM4 port provides native x86 coreboot bootblock, romstage,
ramstage and standard payload builds. Signed vendor PSP/ABL/APCB firmware owns
pre-x86 initialization and DRAM training. The x86 path does not invoke FSP-M or
FSP-S and does not establish cache-as-RAM. Read the
[AMD Family17h documentation](../../soc/amd/family17h.md) with this description;
its Picasso examples do not establish desktop AM4 binary compatibility.

The flash image is32MiB; the bench flash voltage is documented as3.3V.
This branch publishes the source111 functional milestone, with normal
`alpha125-CSM` EDK2 and `alpha126` SeaBIOS version profiles. It remains an
**ALPHA** with explicitly bounded hardware qualification.

SDK identification and ordinary make commands. Hardware dumps, NVRAM, credentials

Each name has the prefix `configs/config.asrockrack_b565d4_v1l_`. Backends are
selected at build time; this is not vendor-style automatic switching among
every AM4 CPU. Historical Ryzen5500 and3700X runs belong to separate cohorts.
Ryzen1000/2000 and arbitrary additional CPU models are not qualified.
The adopted desktop capacity remains16 logical CPU slots; private32-thread
work is not part of this branch.

## Functional milestone

The latest physical cohort uses a Ryzen5 5600X B2 and one32-GiB ECC UDIMM.
Standalone SeaBIOS and EDK2/native UEFI/embedded CSM boot the SATA Proxmox
installation with all twelve threads. Earlier protected cohorts establish
original USB and native NVMe boot. These results do not imply one exhaustive
cross-product of every CPU, payload, DIMM and boot device.

Native memory ownership follows the bounded actual APOB map. The installed
capacity is usable, EDAC reports32GiB, free-memory pattern tests pass, RTC
advances and ACPI tables have been checked/disassembled. Physical ECC correction
and the planned4x32-GiB configuration remain unqualified.

PCIe enumeration and SMU-assisted Gen3 training work for the tested topology.
The normal default is x16; CMOS/setup can select bifurcation. Device visibility
depends on which lane groups are populated. IOMMU uses native groups without
an ACS override. Isolated PF/VF passthrough and basic SR-IOV have passed bounded
KVM tests; shared chipset groups are preserved as groups. The accepted CCP
policy hides its PCI function. This does not claim an operational cryptographic
accelerator.

The CSM application uses a temporary firmware helper and releases its ownership
before OS takeover; no CPU remains permanently reserved. All twelve threads,
matching MTRRs, KVM and nested KVM are witnessed. A completed earlier cohort ran
host12h/guest6h. The final operator-concluded run passed19h53m59s of host
verification with six CPU stressors and a locked24-GiB VM stressor. All seven
stressors passed;14299 native samples/4,976,052 genuine8-byte MCA STATUS reads
and all four EDAC counters remained zero. The guest passed almost12h of
verification, measured43199.659932869s by the host. The final run is not labelled
a completed24h-host/12h-guest test. Maximum observed Tctl was86C with passive
cooling. These observations establish bounded stability, not a universal
guarantee against future hardware errors.

EDK2 includes native storage/network drivers, Shell, the default coreboot logo,
LVGL setup, persistent EFI variables, embedded CSM and Intel UNDI/iPXE support.
The physical HTTP path loaded an EFI test application. A complete physical
network-root Linux boot remains a follow-up. GUI and nvramcui settings share
the board option schema. Native fixed-power-button input and orderly S5 have
physical evidence.

## Remaining scope

* Root-port own-INTx routing remains unqualified; earlier endpoint INTx and
  normal MSI paths have separate positive evidence.
* Both Mellanox cards lacked an external peer. Link/speed selftest failures
  are expected in that setup. Internal RX loopback remains unresolved and
  does not establish a firmware cause; actual connected traffic is unqualified.
* The tested Crucial P1 needs the ordinary Linux `admin_page_align` quirk for
  the observed APST buffer-boundary problem. Its separate worn-drive health
  warning is not corrected by firmware or by that mitigation.
* Deep package/DF sleep, S3 resume, visible monitor output,128GiB, physical
  ECC correction and additional CPU models are not qualified. GOP/BGRT and
  framebuffer observations do not substitute for a visible-display test.

The operator accepted the functional milestone and concluded the work on
2026-11-05. The target was shut down normally and the bench AC switch left off.
No new hardware action is implied by building or publishing this source.
