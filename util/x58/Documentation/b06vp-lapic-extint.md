# B06VP BSP LAPIC ExtINT experiment

## Purpose

B06VP preserves B06VO's vendor-assisted initialization, bounded RAM tests,
QPI, X58 routing, selective-PCI, physical-Radeon-VBIOS, SeaBIOS and
RTL8168-iPXE path.  It changes only the BSP local-APIC virtual-wire setup
during ramstage device initialization.

The experiment tests one explanation for the B06VO payload boundary seen
twice, with persistent UART silence measured in one retained long run:

```text
missing LAPIC LINT0 ExtINT virtual-wire routing
  -> legacy 8259 IRQ0 does not reach the BSP
  -> the BIOS Data Area timer tick does not advance
  -> iPXE remains in sti; hlt while waiting for its next tick
```

The 2026-09-06 HW-03 run resolved this boundary: the selected LAPIC gate
passed, SeaBIOS/iPXE advanced beyond the former wait, Ethernet link and DHCP
succeeded, a 388,848-byte NBP was transferred by TFTP, and the netboot.xyz
menu appeared.  The earlier blinking VGA text cursor alone was not proof of
CPU progress because it is generated by the VGA CRTC.

## Why the keyboard observation is not yet a separate root cause

SeaBIOS initialized the two ICH10R EHCI functions and all six UHCI functions
in B06VO-HW-04, but its trace contained no USB/HID-device enumeration.  Its
i8042 path also returned `ff` and timed out.  A working keyboard is therefore
not established.

However, SeaBIOS services USB, PS/2 and serial-console input events from the
same periodic clock path.  If IRQ0 never reaches the CPU, the iPXE countdown
and all three input paths can appear dead together.  B06VP deliberately fixes
the common timer-delivery prerequisite first; it does not add USB routing or
keyboard-specific writes.

## Exact hardware delta

The B06VO device tree and payload configuration remain unchanged.  B06VP adds
one `.init` callback to the single enabled CPU-cluster device.  That callback:

1. reads `IA32_APIC_BASE` with `RDMSR`;
2. refuses LAPIC MMIO unless the high dword is zero, the base is
   `0xfee00000`, xAPIC is enabled, x2APIC is disabled, and the processor is the
   BSP;
3. logs pre-state TPR, SVR, LVT0 and LVT1;
4. invokes upstream coreboot `setup_lapic_interrupts()` exactly once;
5. re-reads and revalidates `IA32_APIC_BASE` before further LAPIC MMIO;
6. logs the post-state and requires the selected fields below.

```text
TPR[7:0]                       = 00
SVR.enable                    = 1
SVR.vector                    = 0f
LVT0.mask/trigger/polarity    = unmasked / edge / high
LVT0.delivery mode            = ExtINT
LVT1.mask/trigger/polarity    = unmasked / edge / high
LVT1.delivery mode            = NMI
```

The helper performs masked updates, so unrelated/read-only bits are retained
and the complete printed register values are not required to be zero outside
the listed fields.  B06VP does not initialize application processors, IOAPIC,
PIC, PIT, USB, memory, QPI, IOH, PCIe or the GPU.  It retains:

```text
CONFIG_SMP=n
CONFIG_XAPIC_ONLY=y
CONFIG_NO_PCAT_8259=n
CONFIG_SEABIOS_HARDWARE_IRQ=y
CONFIG_IPXE_NO_PROMPT=n
```

## Diagnostics

Expected new serial lines are:

```text
[LAPIC] B06VP PRE IA32_APIC_BASE=00000000:fee00900
[LAPIC] B06VP PRE TPR=........ SVR=........ LVT0=........ LVT1=........
[LAPIC] B06VP POST IA32_APIC_BASE=00000000:fee00900
[LAPIC] B06VP POST TPR=........ SVR=........ LVT0=........ LVT1=........
[LAPIC] B06VP BSP virtual-wire ExtINT/NMI gate PASS
```

POST codes added by this build are:

```text
40  BSP LAPIC setup is about to execute
42  selected LAPIC post-state passed
43  APIC-base, BSP/single-call or selected-field gate failed; terminal halt
```

All earlier B06VO diagnostics remain in force.  A `42` proves only the LAPIC
register readback.  Actual timer delivery is established only by payload
progress beyond the former wait boundary.

## First hardware procedure

Use the same fixed E5645, sole SPD-`0x54` DIMM, HD 5450 and RTL8168 setup as
B06VO.  Arm COM1 `0x3f8` at 115200 8N1 before power-on and retain the complete
trace.  Flash only the complete 16-MiB W25Q128 image whose hash is listed in
the B06VP manifest; verify it externally before applying power.

For the first execution, do not press a key.  The decisive observations are:

- the B06VP PRE/POST lines and `PASS` marker appear;
- the unchanged SeaBIOS, physical Radeon VBIOS and iPXE prompt appear;
- the prompt timeout advances and returns rather than remaining indefinitely
  after its first `INT 16h AH=01` entry and source-derived timer wait;
- later SeaBIOS/iPXE serial output appears.

Only on a separate repeat should Ctrl-B be sent during the prompt.  A serial
iPXE shell would prove both periodic wakeups and the SeaBIOS serial-input
path.  USB keyboard enumeration and input must still be judged independently
from the USB trace; a responsive serial Ctrl-B does not prove USB HID.

If POST `43` appears, retain the complete PRE/failure line and stop.  If no
serial output follows the LAPIC begin code, retain the physical POST code and
recover with the known-good B06VO or vendor chip.  Do not add a second register
hypothesis before interpreting the first trace.

## Hardware outcome and proof boundary

B06VP is built twice byte-identically, statically tested and independently
audited.  HW-03 proves the selected LAPIC readback, payload timer progress,
visible Radeon output, RTL8168 link, DHCP, TFTP and execution through the
netboot.xyz menu in one complete run.  It does not by itself distinguish every
possible source of IRQ0 delivery, but the exact B06VP delta was sufficient to
remove the B06VO boundary.

The same trace initialized both EHCI and all six UHCI controllers without
enumerating a USB device.  Its i8042 probe returned `ff` and timed out.  USB
HID, PS/2, SATA/storage, an OS boot, SMP/AP startup, ACPI completeness and the
stable 10-cold/10-warm result remain unproved.
