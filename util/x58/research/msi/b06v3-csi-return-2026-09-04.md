> described below as extended CMOS were read with ICH10 U128E clear and thus
> came from aliased standard RTC clock/calendar registers. They must not be
> treated as upper-bank CMOS policy.

## Confirmed boundary

The first CSI call produced the expected reset. B06V3 then accepted exactly
the retained I801 state it had previously programmed:

```text
BAR4=00000401 HOSTC=01 CMD=0001
[SMBUS] ENTRY=CONFIGURED_AFTER_RESET
```

The fresh ROMMON retained the expected platform tuple:

```text
CPUID=000206c2 UCODE=0000001f
SPD_FNV=fb66b530 ACKMAP=10 DDR3MAP=10
QPI80=030f0f03 MC50=0a000006 MC54=00000006
PCIEXBAR=00000000:e0000001
```

After repeating the passive gates and `vprep`, the second isolated `vcsi 00`
returned:

```text
CSI_CALL STATUS=ok CODE=00
EAX=00000002 EBX=00000002 ECX=00000106
EDX=fff8fcd8 EDI=fff8fcd8 EFLAGS=00000086 VESP=fff8ffe4
CSI_FNV=c4eab5a4
private-stack HIGHWATER=00000454
```

All four vendor range signatures and all CAR canaries remained valid. The
exact tuple and complete `0x304`-byte state digest were accepted with
`vaccept 2 2 106 c4eab5a4`. This proves a repeatable reset/continuation ABI
boundary and a real vendor-code return. It does not establish the semantic
meaning of return value `2`, successful QPI training, memory initialization,
or usable DRAM.

## Policy-input correction

The old B06V3 `vpolicy reset` rejected the state as “RTC/CMOS invalid”. Static
analysis then showed that it had confused extended CMOS `0x8e` with standard
CMOS diagnostic byte `0x0e`. Read-only observations from the returned state
were:

```text
standard CMOS 0e = 6c
extended 81/82/88/89 = 19/f7/6f/cb
extended 8e/ca/f1/f5 = 6c/62/91/e9
PMBASE+38 low byte = 00
```

The standard byte and extended `0x88` values shown above are the later B06V4
selector-controlled corrections; the original ad-hoc B06V3 reads reported
`0x62` and `0x67` because they did not re-establish the selectors
independently. The original MSI wrapper skips its conditional CMOS-policy
block when
standard diagnostic bits 7:6 are nonzero. It separately bounds extended
`0x8e` to `0x30` before deriving policy byte `0x02`. It reads only the low byte
of ICH10 `ALT_GP_SMI_EN` and extracts bits 6:4. B06V4 implements these
distinctions without writing CMOS data.

## Register-script hardware proof

A 16-operation table selected and read eight extended CMOS bytes. The table
was sealed as `PROGRAM_FNV=54538d2c`, ran successfully with transaction digest
`d0cd7a2c`, and recorded eight reversible port-`0x72` selector mutations. The
explicit reverse-order rollback verified every restored selector value and
finished at transaction digest `6c3c2814`, `ROLLED_BACK=01`.

Generic script execution correctly changed `ROMMON_DIRTY` to one and
invalidated the SPD/vendor gate for the remainder of that boot. Long unpaced
command bursts also produced bounded UART receive errors rather than executing
damaged lines. These are safety results, not memory-training progress.
