No programmer read-back was captured. The full-chip identity is therefore the
expected installed artifact, not an independently measured flash hash.

## B06VN-HW-03: fail-closed CPU-A0 rejection

The first hardened retry completed the two intended CSI continuation resets.
Its two consecutive pre-call CPU-A0 reads agreed at `0x00016e00`, but that
value is outside
B06VL's exact seven-value admission set
`17000|17200|17400|17600|17800|17a00|17c00`. The firmware therefore made no
MINIT call, printed
`AUTO_FALLBACK=B06VG_PRE_A0_STABILITY_GATE`, and returned safely to ROMMON.
This is a correct guard result and also direct evidence that the pre-call
state is not yet deterministic across relay cold-cycle attempts.

The operator then issued `unlock RESET` followed by `autoguard clear` and
observed read-back change from `0xec` to `0x2c` before HW-04. That command
exchange was not retained in either audited capture; HW-04 itself does log
the resulting `CMOS0E=2c` initial state.

## B06VN-HW-04: independent clean payload repeat

The next one-second relay interruption produced the admitted tuple:

```text
PRE_A0=00017800
POST_A0/CPU9C=00017800/00a00502
CSI raw/canonical=03e3d24e/908dabb6
workspace raw/canonical=2f55481f/92c70df4
MINIT EAX=00000000
HARD_RETURN_GATE=PASS
```

The complete 640-KiB uncached low-memory test and both complete 8-MiB
uncached windows passed. CBMEM, postcar, and real coreboot ramstage followed.
Root `00:03.0` again reported Gen1 x16, `DLLA=1`, `LT=0` before B06VN's
conditional action, so the `+0x190=0x000c` write was again skipped.

The result after enumeration exactly reproduced HW-02's important boundary:

```text
01:00.0 GPU identity: absent/unreadable
02:00.0 RTL8168 identity: 10ec:8168
SeaBIOS PCI count: 98
SeaBIOS VGA result: No VGA found
option ROM: embedded RTL8168 iPXE executed
capture marker: first logged INT 16h AH=01 entry during the iPXE Ctrl-B poll
```

Immediately after the capture released the TTY, the operator sent Ctrl-B/Enter
twice through a fresh 115200-8N1 picocom session and observed no UART response.
That interaction was not retained as a separate serial artifact. Together
with the quiet marker linger it strengthens the hypothesis that execution
stops in or immediately after the first SeaBIOS INT 16h path; it does not by
itself identify the instruction or prove an IRQ/PIC/PIT root cause.

## Capture integrity

HW-04 was captured with a project flock, kernel `TIOCEXCL`, no discarded
prefix, and an aggregate 115200-8N1 line-rate-envelope check. It captured
68,088 bytes over 1,180.928 seconds, or 57.656 bytes/s. The terminal marker was
`enter handle_16:`. The aggregate envelope passed and there is no HW-02-style
large replay prefix; the metadata does not prove the absence of every possible
short local burst.

## Next isolated experiment

The clean repeat independently reproduced the 32 bus-2 aliases of X58
internal functions and the missing GPU endpoint. The next build should repair
only the established IOH configuration-routing defect: conditionally set and
verify `00:14.0+0x10a IOHBUSNO=0x0100`, log aliases before and after, and read
the newly assigned root-03 secondary endpoint through both CF8/CFC and direct
PCIEXBAR. Secondary-bus reset, `LNKCAP` correction, and SeaBIOS hardware-IRQ
changes remain separate follow-up hypotheses.
