0.5-second quiet gate discarded zero bytes before the exact one-second relay
cycle.  The automatic 30-minute deadline and ordinary marker policy were not

UART byte arrived for at least 120 seconds.  The recorder was then deliberately

## Repeated VBIOS and display result

SeaBIOS again mapped the physical Radeon ROM at `0xcff20000`, validated its
59,904-byte AA55 image, copied it to C0000 and entered `c000:0003`.  It then
continued through VGA text-console, USB, disk and option-ROM initialization,
which proves that the physical VBIOS returned.  The operator first reported
visible output and then supplied a photograph showing this exact screen:

```text

iPXE (https://ipxe.org) 02:00.0 CF00 PCI2.10 PnP PMM+BEFDE3E0+BEF1E3B0 CF00

```

The photograph is retained in the conversation but has no independently
hashable repository copy.  It independently matches the UART identity and
last visible prompt; this upgrades display output from an unrecorded operator
statement to direct visual evidence without making the image part of the raw
serial artifact.

The embedded RTL8168 iPXE ROM subsequently started and satisfied its PCIBIOS
and PMM calls.  The last retained output is:

```text
Press Ctrl-B to configure iPXE (PCI 02:00.0)..enter handle_16:
   a=00000100 ... f=0246
```

There was no subsequent byte for at least 120 seconds.  Unlike HW-02's
marker-limited recording, HW-04 therefore supplies one persistent-silence
observation at the payload boundary after the successful VBIOS return.  It
does not by itself establish reproducibility of that silence or its cause.

SeaBIOS did initialize both ICH10R EHCI functions and all six UHCI functions,
but the trace contains no USB-device or HID-keyboard enumeration.  Each
controller's temporary pipe state was released.  The fallback PS/2 path read
only `status=ff` and ended in `WARNING - Timeout at i8042_flush:71!`.
Therefore no working keyboard is evidenced in this run.  Source analysis
predicts that, if the observed silence is caused by the missing periodic
wakeup, even serial Ctrl-B will not be serviced; this is an inference rather
than a separate dynamic observation.  USB port routing/power and HID
enumeration should be isolated only after the IRQ0 timer path is tested.

## Timer/interrupt root-cause hypothesis

The apparent boundary is the first SeaBIOS `INT 16h`, but source inspection
shows that `AH=01` is a non-blocking keyboard-status request.  iPXE's
`wait_for_key` then calls `wait_for_tick`, which repeatedly executes `sti; hlt`
until the BIOS Data Area timer count at `0040:006c` changes.

SeaBIOS was built with hardware IRQ support and initializes the legacy PIC and
PIT.  The custom single-CPU X58 ramstage, however, gives its CPU-cluster device
no `.init` callback.  Normal coreboot CPU initialization calls
`setup_lapic_interrupts()`, which clears LAPIC task priority, enables the
spurious-vector register, routes legacy PIC interrupts through unmasked LINT0
in ExtINT mode, and configures LINT1 as NMI.  That routine exists in the
ramstage object archive but was dead-stripped from the B06VO final ramstage,
because the custom path never references it.  Earlier telemetry proves an
enabled BSP xAPIC base (`IA32_APIC_BASE=fee00900`) but does not prove a usable
LINT0 virtual-wire configuration.

The strongest current inference is therefore:

```text
missing LAPIC LINT0 ExtINT virtual-wire setup
  -> legacy PIC IRQ0 is not delivered to the BSP
  -> BDA timer tick does not advance
  -> iPXE remains in sti; hlt after its first keyboard-status check
```

This is not yet hardware proof.  The next one-delta image must log the LAPIC
registers, invoke the existing coreboot virtual-wire initializer once on the
BSP, require exact masked-field readback, and leave SeaBIOS hardware-IRQ and
iPXE prompt behavior unchanged.  Simply disabling the prompt would hide this
first wait while leaving later BIOS and iPXE timers broken.

## Conclusion

B06VO now has two complete one-second-relay executions through memory,
coreboot ramstage, corrected X58 PCI routing, Radeon enumeration, physical
VBIOS return, visible display and RTL8168 iPXE entry.  HW-04 additionally
records one persistent post-VBIOS UART-silence interval and gives a narrow,
testable interrupt-routing hypothesis.  It is still not a 10-cold/10-warm
validation set; no electrical G3, programmer read-back, network link, DHCP,
storage or OS boot is claimed.
